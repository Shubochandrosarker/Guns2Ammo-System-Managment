Section 04

v1.7 Deep Dive — Customer Experience

Request-a-different-dealer flow

Visible on the public tracking page only while the parcel is still pre-arrival (statuses payment_confirmed, dealer_selected, shipped_to_dealer, shipped). Form submits to admin-post.php?action=wpistic_ffl_track_request_dealer, which:

  1. Re-verifies the tracking signature so only the email recipient can submit.
  2. Validates honeypot + nonce.
  3. Inserts an events row with event_type='dealer_change_requested'.
  4. Fires an admin email with the customer's reason + preferred new ZIP.
  5. Redirects with ?req_done=1 showing a green confirmation.

Admins see the request in the Activity Log feed and can act from the transfer detail page.

.ics calendar invite

RFC 5545 single-event calendar attachment auto-bundled with the "Item Arrived at Dealer" email. The event:

  • Starts at the next business day at 12:00 local site timezone (skips Sat/Sun)
  • 30-minute window
  • STATUS:TENTATIVE — customer can confirm with the dealer first
  • VALARM with 1-hour reminder
  • LOCATION contains dealer name + full address (works as Google/Apple Maps deep-link in most calendar apps)
  • DESCRIPTION lists what to bring: government ID, state permit if any, payment for the transfer fee

Spanish (es_US) tracking page

Lightweight per-string translator triggered by ?lang=es. Header link toggles between English / Español. Translates 13 customer-facing strings — covers the visible UI without requiring a full WordPress locale switch (which would affect every other site visitor too).

Checkout contrast bug fix

Before: dealer card titles ("AREA 15"), result count ("30 dealers found near Mesa, AZ"), and "Contact Dealer for Fee" were styled with color: var(--wf-ink) — the dark-on-brass-button contrast color — but rendered on the dark --wf-surface background, making them effectively invisible.

After: every text node now uses var(--wf-text) (light). Recommended + selected card variants reskinned with brass-tinted-on-dark backgrounds instead of light gradients. Active filter tab swapped to brass-on-ink for stronger brand alignment.

Section 05

v1.7 Deep Dive — Operations

Outbound webhook dispatcher

Admin page at FFL → 🔌 Webhooks Out. Each configured endpoint has:

  • URL (full https://…)
  • Shared HMAC secret (auto-generated, rotatable)
  • Event filter (subscribe to specific events or all)
  • Enabled toggle

On every dispatch, the body is signed via X-Wpistic-Ffl-Signature: hash_hmac('sha256', body, secret). Failures (non-2xx or transport error) automatically queue a retry through G2A_Scheduler at the next backoff offset (1m → 5m → 30m → 2h → 12h, 5 attempts max). Every attempt is logged to analytics_events for the Activity feed.

Operations Toolset

Admin page at FFL → 🛠️ Ops Tools. Three operations features in one panel:

ToolWhat it does
Bulk dealer feesSet the transfer fee for every active dealer in a state in one click. Optional safety filter: "only if currently 0.00" — avoids overwriting hand-set fees.
Customer LTV lookupSearch by email. Returns count of transfers, lifetime value (sum of WC order totals), avg days from order → pickup, last dealer used, and a recent-transfer table with one-click jumps into WC orders.
Dealer health alertsNightly cron flags dealers whose 90-day issue_reported rate exceeds 25% (min 5 transfers). Flagged list rendered on the page; admin email fires when a new dealer joins the flagged list.

Per-dealer Scorecard PDF

Admin-only URL: /ffl-scorecard/{dealer_id}/. Browser-printable HTML page with:

  • 90-day window KPIs: total transfers, in-flight, completed, issues, avg ship→arrival days
  • Portal stats: tokens issued, confirmations, confirmation rate
  • Recent transfer list (15)
  • Brass-on-graphite cover + tabular metrics, print stylesheet hides the toolbar

Useful as a quarterly ATF compliance deliverable and as a courting artifact when onboarding larger FFL partners.

Section 06

v1.7 Deep Dive — Compliance & Security

Admin TOTP 2FA

Opt-in per admin user from Users → Profile → 🔐 FFL Admin Two-Factor (TOTP). Enrollment flow:

  1. Admin clicks "Enable TOTP" — server generates a 20-byte RFC-4226 secret + 8 backup codes.
  2. QR rendered via api.qrserver.com (URL-encoded otpauth:// URI; no library dependency).
  3. Admin scans with Google Authenticator / 1Password / Authy, enters the first 6-digit code to confirm.
  4. On success: secret AES-256-CBC encrypted with a NONCE_SALT-derived key, stored in user meta. Backup codes SHA-256 hashed, stored as an array.

On every admin page load (excluding ajax + cron), if the user has TOTP enabled and no 12-hour challenge transient is set, a full-screen brass-themed modal blocks the UI until a valid code (or backup) is entered. Validated against RFC 4226 test vectors at smoke time.

GDPR personal-data hooks

Registered with wp_privacy_personal_data_exporters and _erasers filters — appear in Tools → Export/Erase Personal Data automatically.

  • Export: dumps every transfer row matching the customer email + every saved-dealer entry tied to the user account, paginated 50 per page.
  • Erase: anonymizes customer_name, customer_email, customer_phone, customer_id fields to REDACTED / redacted@example.invalid. Row is retained because federal ATF rules require multi-year retention of transfer records. Saved-dealer user meta deleted in full.

Form 4473 worksheet

Browser-printable HTML at /ffl-4473-draft/{transfer_id}/, admin-only. Pre-fills the same field labels as the official ATF Form 4473 from the transfer record (firearm make/model/serial, customer info, NICS NTN, dealer info). Banner-stamped "DRAFT — NOT FOR ATF SUBMISSION" on every page. Footer disclaimer covers the legal boundary.

50-state law engine top-up

G2A_State_Laws::baseline_rules() ships entries for 42 previously-unseeded states. Hand-tuned states (CA / NY / NJ / MA / MD / IL / HI / CO / WA + DC) are preserved unchanged. Default rule for low-regulation states is a neutral "Standard federal NICS background check required" notice — better than the empty state the front-end was previously showing.

Public dealer onboarding

Drop the shortcode [g2a_ffl_dealer_onboard] on any page. Renders a brass-themed form with business name, FFL number, contact details, premise ZIP, suggested fee, free-form notes. Submissions:

  • Per-IP rate limit (3/hour) via transient.
  • Honeypot field.
  • Audit-logged to events.
  • Admin email fires with reply-to set to the dealer's contact email.
Section 07

Complete Workflow Reference

Customer workflow (buy → pickup)

  1. Order placed → FFL dealer selected at checkout. Logged-in repeat customer sees their saved-dealer quick-pick strip; otherwise full search.
  2. Payment confirmed → transfer row inserted, customer "Order Confirmed" email sent with View-Status CTA, dealer portal email queued asynchronously.
  3. Shipped → admin enters carrier + tracking number; status auto-advances to shipped_to_dealer, customer notified via email + SMS.
  4. Carrier reports delivered (live tracking) OR dealer confirms via portal → status flips to received_by_dealer; customer email + .ics invite + SMS for "ready for pickup" sent immediately.
  5. NICS → admin records check date / NTN / 4473 ref; delayed flips the 3-day clock; nightly cron alerts on expiry.
  6. Transferred → customer celebration email; WC order auto-completed via status bridge.

Dealer workflow (receive → confirm)

  1. Magic-link email arrives. Click goes to /ffl-confirm/{token}/.
  2. 2FA challenge: last-4 of FFL license OR 6-digit email OTP (admin's choice).
  3. Pick action: Item Received / Report Issue / Not My Shipment.
  4. Token consumed, transfer advances, admin notified, customer informed.

Admin workflow (monitor → act)

  1. FFL → 📊 Dashboard for the daily snapshot.
  2. FFL → 📋 Activity Log for the unified event feed.
  3. FFL → 🛡️ Compliance for the 15-check health audit.
  4. FFL → 🛠️ Ops Tools for bulk fees, customer LTV, dealer health.
  5. FFL → 📦 Carriers for live-tracking config.
  6. FFL → 🔌 Webhooks Out for CRM / Zapier wiring.
