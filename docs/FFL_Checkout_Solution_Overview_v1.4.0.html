Section 01

Executive Summary

The Advanced FFL Checkout plugin handles every step a Guns 2 Ammo customer goes through when they buy a firearm online: choose the receiving FFL dealer at checkout, track the shipment, watch the NICS background check progress, and pick up the gun. Behind the scenes the plugin also runs the FFL workflow for the operations team — every status change is logged, every dealer touch is signed with a single-use HMAC token, and every regulatory checkpoint (HPOS, ATF, NICS 3-day rule) is enforced or automated.

What ships in v1.4.0

  • FFL dealer search at WooCommerce checkout — ZIP / name / license / phone filters, distance via Haversine, optional Google Maps view, no required API keys.
  • 11-stage transfer pipeline with append-only audit log, NICS NTN + ATF Form 4473 reference fields, multi-carrier shipment tracking.
  • HMAC-signed dealer confirmation portal — magic-link email, single-use token, configurable 2FA (last-4 of FFL), honeypot, rate-limit, full audit IP trail.
  • Customer-facing tracking page at /track-transfer/{ref}/ with a 5-step timeline, Maps directions, click-to-call.
  • "My FFL Transfers" tab in WooCommerce My Account.
  • NICS 3-day rule automation — auto-expiry date set Mon–Fri, nightly admin alert when the window elapses.
  • SMS notifications via Verifyistic — fires ffl_transfer_status webhooks at every customer-facing milestone.
  • WC ↔ FFL status bridge — completed orders auto-mark transfers complete, refunded orders cancel transfers, etc.
  • Admin Activity Log + Compliance Audit pages, plus matching JSON endpoints for the standalone G2A dashboard.
  • Full Guns 2 Ammo branding — brass on graphite, native to tokens.css, white-label by default.
Why this matters for revenue: Customers buy firearms online much more readily when they trust the transfer process. Every email shows the dealer card, every status change reaches the customer's inbox + SMS, and every dealer touch is one click. That converts shoppers and removes the manual "where's my gun?" support load.

Section 03

Customer Workflow — Buy → Pickup

From the customer's point of view, the FFL workflow is "I bought a gun and the store keeps me in the loop until I pick it up." Behind the scenes there are five distinct phases. Each phase emits an email (always) and an SMS (when Verifyistic is configured) and is reflected on the public tracking page.

1
Order Placed

Customer selects FFL dealer at checkout, pays, gets order confirmation + transfer ref

2
Shipped to Dealer

Admin enters tracking number — status auto-advances, customer notified

3
Arrived at Dealer

Dealer confirms receipt via secure magic-link portal

4
Background Check

NICS in progress; if delayed, 3-day rule clock starts

5
Transfer Complete

4473 signed, NICS approved, customer takes possession

Step-by-step timeline

Stage 1 · At Checkout

Dealer selection

When the cart contains a product marked "FFL Transfer Required", the FFL widget renders below the billing form. The customer searches by ZIP / name / license / phone, picks a dealer, and sees the transfer fee, dealer phone, and a Google Maps directions link. Honeypot + nonce keep bots out. The dealer ID is validated against the dealers table before being stored on the order (HPOS-safe).

Stage 2 · Payment confirmed

Transfer record created & first email sent

On woocommerce_payment_complete the plugin creates a row in the transfers table with a G2A-XXXXXXXX reference, sends the customer the "Order Confirmed" email (brass-themed, "View Transfer Status" CTA included), and schedules an asynchronous dealer-portal email so checkout never blocks on SMTP.

Stage 3 · Shipping

Carrier auto-advance

When the admin enters a tracking number, G2A_Carrier auto-advances the status to shipped_to_dealer, fills in shipped_date, generates the public carrier URL (UPS/USPS/FedEx/DHL), and triggers the "Item Shipped" email + SMS.

Stage 4 · Arrival

Dealer confirms receipt

The dealer clicks the one-time link in their email. The portal page verifies the HMAC, asks for the last 4 of their FFL license, and on confirmation flips the transfer to received_by_dealer. The customer immediately gets the "Your gun is ready" email + SMS — historically the highest-value customer SMS on the platform.

Stage 5 · NICS

Background check + 3-day rule

When status flips to delayed, G2A_NICS automatically computes the federal 3-business-day expiry (Mon–Fri) and stores it on the row. The nightly cron job emails the admin the day the window elapses (one-shot, idempotent).

Stage 6 · Pickup

Transfer complete

On transferred, the customer gets the celebration email, the WooCommerce order auto-marks "completed" via the status bridge, and the customer-facing tracking page shows all five timeline pips lit brass.

Typical day in the operations chair

  1. Glance at the Dashboard for the green/amber count.
  2. Open the Activity Log — anything red gets a click-through.
  3. For each new "shipped" order, paste in the carrier + tracking number — carrier auto-advance handles the rest.
  4. If the dealer doesn't confirm within 3 days, the reminder cron sends an email automatically.
  5. If NICS comes back delayed, the 3-day rule cron emails when the window elapses.
  6. Compliance page checked monthly — confirms data is fresh and secrets are healthy.

Security layer (token / portal / API)

  • HMAC-SHA256 signed tokens with payload v1.tid.did.action.exp.nonce
  • SHA-256 hash storage — the raw token is emailed to the dealer and never persisted
  • Constant-time comparison via hash_equals() — timing-attack resistant
  • Single-use enforcement at the DB level via used_at column
  • Re-issue invalidates all prior active tokens for the same transfer
  • Per-IP rate limit on portal submissions (5/min) and dealer searches (30/min)
  • Honeypot fields on both the checkout widget and the dealer portal form
  • Nonce on every form submission
  • Trusted-proxy CIDR filter — X-Forwarded-For only honored from configured upstreams
  • Optional HTTPS-only redirect for the portal
  • Optional last-4 FFL 2FA — verifies the link reached a real dealer
  • Full audit log with binary-packed IP + UA for ATF traceability
  • One-click HMAC rotation from the Compliance page
  • wp-config secret nag — pushes admins to the strongest config

Section 09

Admin Surfaces & Activity Log

Activity Log page

Every status change, dealer portal action, NICS event, email send, and customer tracking-page view lands in one table. The feed merges the events and analytics_events tables via a UNION query so it sorts cleanly even when an event came from the portal funnel rather than a status change.

Each row shows: relative time + absolute timestamp, the event label, the transfer reference (one-click to jump in), the actor (system, wc-bridge, dealer-portal, etc.), and a snippet of the notes column.

Compliance & Security page

Top of the page is a four-tile summary (Pass / Warn / Fail / Info), followed by the full check table with one-click remediation links. Below that, a Regenerate HMAC Token Secret button — protected by nonce, capability, and confirm dialog — rotates the secret and revokes every live token in one shot.

Both pages mirror their data to JSON endpoints (see next section) so the standalone app.guns2ammo.com dashboard can render the same information without a second integration pass.

Day-one checklist

  1. Install the plugin (Plugins → Upload → advanced-ffl-checkout.zip).
  2. Define WPISTIC_FFL_TOKEN_SECRET in wp-config.php.
  3. Visit Advanced FFL → Dashboard, click Import ZIP Codes.
  4. Wait for the ZIP import to complete (~5–10 minutes background), then ATF sync auto-starts (~2–4 hours background).
  5. Set the receiving FFL license in Appearance → Customize → G2A Business Info.
  6. Mark firearm products as FFL Transfer Required in their general data tab.
